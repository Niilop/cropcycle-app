# Implementation plans

Use a plan for substantial features, migrations, or work likely to span sessions. Small fixes can stay in a PR description. A plan records the intended outcome and evidence of completion, not a transcript of an agent's reasoning.

1. Copy [TEMPLATE.md](TEMPLATE.md) to `NNN-short-name.md`, choosing the next unused number.
2. Fill in the goal, scope, acceptance checks, and known questions. Start with status `draft`; distinguish proposals from agreed work.
3. Link the plan from [STATUS.md](../STATUS.md) when work becomes active. Multiple independent plans may be linked if needed.
4. Keep the checklist, validation results, and handoff current as the implementation evolves. Record deviations that affect the agreed outcome.
5. Mark the plan `complete` when its acceptance checks are met, or `cancelled` if the work is abandoned. Leave completed plans here as references and remove them from the active-work list.

Use `blocked` when a specific missing decision or external condition prevents progress, and state what is needed. Record unrun checks honestly. Delete unused template sections from individual plans instead of filling them with boilerplate. These files do not trigger work automatically or replace user authorization.
