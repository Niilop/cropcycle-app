Original preliminary requirements from the product owner, received 2026-09-28. Kept as the source statement; implementation choices that refine or deviate from it are recorded in [DECISIONS.md](../DECISIONS.md) and [plan 002](../plans/002-crop-rotation-mvp.md). Do not edit this file to reflect later decisions — add a new version instead.

## 1. Goal

Build a mobile-first crop rotation planning app for iOS and Android.

The app helps users:
- define garden beds/patches
- record crop history
- plan crops for a future season
- manually place preferred crops first
- automatically suggest placements for remaining crops
- consider crop rotation and neighboring crop compatibility
- override all suggestions freely

The app provides guidance only. It must not block suboptimal planting choices.

## 4. Main User Flow

### Garden setup
User can:
- create a garden
- add rectangular beds
- move/resize beds
- rename beds
- delete beds

### History
For each bed, user can add:
- crop
- year
- approximate start/end month

Multiple sequential crops can exist in the same bed during one year.

Example:

April–June: lettuce
June–September: beans

### Create yearly plan
User selects:
- planning year
- crops they want to grow
- quantity for each crop

Example:

- Carrot ×2
- Potato ×2
- Pea ×1
- Onion ×1

### Manual placement first
User can place crops into desired beds.

Manual placements are locked by default.

The recommendation engine must preserve locked placements.

### Fill remaining
User taps:

**Fill remaining**

Backend generates placements for all unassigned requested crops while respecting locked placements.

Factors:
1. crop rotation history
2. crop family rotation
3. neighboring crop compatibility
4. available seasonal time
5. existing locked placements

User can freely modify the generated plan afterward.

## 5. Recommendation Behavior

Do not classify ordinary choices as forbidden.

Use simple states such as:

- Very suitable
- Suitable
- Possible
- Some considerations

Avoid strong red/error states unless placement is genuinely impossible.

Each recommendation should optionally expose short reasons:

- Good rotation interval
- Same crop grown recently
- Compatible neighbor
- Less compatible neighbor
- Fits available season
- Limited seasonal space

No conversational/LLM-style prose is required.

---

## 6. Auto Layout

Endpoint:

`POST /plans/{plan_id}/generate-layout`

Input:
- plan
- requested crops
- existing locked placements

Output:
- suggested placements
- optional suitability score
- short reason codes

The layout algorithm should optimize the entire plan rather than assigning each crop independently.

Locked/manual placements must never be changed automatically.

For MVP, use a simple weighted scoring/search implementation.

Possible score:

```text
rotation_score
+ family_rotation_score
+ neighbor_score
+ timing_score
```

Do not require OR-Tools for MVP.

Algorithm implementation should be isolated so it can later be replaced with a constraint solver.

## 10. Seed Data

Ship initial data for approximately 30–50 common garden crops.

Each crop should include:
- name
- crop family
- approximate growing period
- basic rotation interval

Include companion relationships where useful.

All agricultural rules should live in database/configuration data rather than frontend code.

---

## 11. Out of Scope for MVP

Do not build yet:
- simultaneous mixed crops within one bed
- partial-bed graphical subdivision
- weather integration
- fertilizer planning
- watering tracking
- harvest/yield tracking
- seed inventory
- disease prediction
- AI/chat assistant
- complex optimizer
- community/social features

Keep the data model extensible enough for partial bed coverage later.

---

## 12. MVP Success Criteria

The user can:

1. Create a garden and beds.
2. Record several years of crop history.
3. Record sequential crops within the same year.
4. Create next year's crop list and quantities.
5. Manually place crops in preferred beds.
6. Lock those decisions.
7. Automatically fill remaining crops.
8. See rotation/neighbor suitability visually.
9. Move suggested crops manually.
10. Save and reopen the plan on iOS or Android.

The core principle is:

**The user chooses first. The app optimizes around those choices.**
